# 定点、AXI 与 FIR/FFT 的 PL 实现和优化

用于将明确算子下沉 PL，或优化已存在的数据通路。
窗口、通道、系数、FFT 长度和总线宽度均从新工程契约取得。
先建立可独立检查的结果，再讨论资源和速度。

## 输入与输出契约

输入：独立黄金参考、目标器件/时钟、数值格式、接口、负载与性能边界。
输出：逐级数值对照、接口时序检查、实现报告、同输入 A/B 和适用范围。
用 [optimization-review.md](../templates/optimization-review.md) 固定比较口径。
Vivado 只读盘点脚手架见 [vivado-interface-checks.tcl](../templates/vivado-interface-checks.tcl)。
该脚手架需要填写目标并在已有设计中运行，不构建 IP，也不替代 CDC/时序验收。

## 冻结数值语义

| 层级 | 需要写入契约 |
|---|---|
| 输入 | 单位、补码/无符号、有效位、全幅、通道顺序、无效码 |
| FIR | 系数来源与 SHA、Q 格式、抽头顺序、历史长度、抽取相位 |
| 运算 | 乘法/累加位宽、符号扩展、每次截位位置、舍入与饱和 |
| 窗函数 | 周期/对称定义、量化、系数索引、幅值或能量校正 |
| FFT | N、实数/复数、正逆变换、自然/位反序、缩放或 block exponent |
| 输出 | bin/通道/窗口身份、单位、功率/幅度/PSD、完成与冻结规则 |

不要以 `Q15` 三个字符替代整数位、符号位和舍入定义。
对 Bx 位有符号输入与 Bc 位系数，乘积常用 Bx+Bc 位表示。
T 项直接累加的保守宽度为 Bx+Bc+ceil(log2(T))，还需检查实际幅值界。
对称 FIR 的 `x_left+x_right` 需先扩 1 位，再乘系数。
先截窄再相加与全精度累加后截窄语义不同；优化时不能互换。
需要更窄位宽时，给出输入约束和误差预算，不从一次通过的测试推断安全。

## 先把数据流映射到实际资源

不要以提高资源占用率作为目标。目标是满足正确性、吞吐和时延，并留下可维护余量。
从每秒输入记录数和每记录运算量估算需求，再选择并行、复用和存储结构。

| 资源 | 常见工作 | 设计时要问的问题 | 需要的实证 |
|---|---|---|---|
| DSP | FIR乘加、复数运算、窗口乘法 | 乘法位宽、每输出乘法数、复用节拍、是否有预加法器 | 综合映射、实际DSP用量、数值边界 |
| LUT | 控制、寻址、比较、总线与小算术 | 控制是否成关键路径，宽多路器/扇出是否过大 | 层次利用率、关键路径与接口测试 |
| FF | 流水寄存、状态与握手 | 切分组合路径的收益，额外延时与复位开销 | 时序、valid对齐、状态恢复 |
| BRAM/URAM | 历史窗、系数、缓冲与结果 | 位宽/深度/端口、并发读写、bank冲突 | 实际RAM推断、端口时序和边界输入 |

这些是候选映射，不承诺某段 RTL 必然推断为指定原语。
目标器件不含某资源时，以实际架构重新选型，不照搬资源名称。

用下面的设计工作表连接需求与结果：
1. 数据流：列各级输入/输出速率、记录大小、批量窗和连续历史需求。
2. 运算率：每输出乘加数×输出率×通道数，注明是否已利用对称/稀疏性。
3. 存储率：历史/系数/结果容量，以及每周期读写端口数和外部搬运带宽。
4. 排程：给出可用时钟、目标II、共享核服务时间和最坏排队时间。
5. 资源：记录估计、综合、实现三种数值，不能将估计栏冒充routed结果。
6. 校验：绑定定点黄金参考、背压/边界测试、真实约束与源身份。
7. 整体验收：核周期、搬运和完整API分别同输入A/B，判断是否值得复杂化。

对称 T 抽头 FIR 可将成对输入先相加，共用同一系数，奇数长度另留中心项。
其逻辑乘法项由 T 降为 (T+1)/2，但DSP数量是否下降取决于复用、流水和工具映射。
共享 FFT 使多通道复用一核，代价是调度、输入/输出存储和作业身份管理。
增加流水可能改善频率，代价是FF、延时与valid对齐；频率提高不自动降低总API耗时。
BRAM banking 可提高端口并行度，需同时证明bank映射和读写冲突处理。
若 PS 经 AXI-Lite 逐字送料，核外搬运可能占主导；先测量再评估批量/DMA方案。
提出 DMA 不等于已实现自主流式链路，计划与已有工程必须分开。

本仓库案例的PS送料、对称FIR和共享8192点Hann/FFT实现见 [evidence.md](evidence.md)。
其641/321/129/65抽头和50/25/10/5kHz→5kHz配置是案例参数，不是新任务默认值。
实际资源与性能结论以该案例绑定的源和报告为准，不从这些参数推导虚构收益。

## 黄金参考必须有独立性

优先使用数学规格或独立实现，而非逐行翻译 RTL。
把滤波、抽取、加窗、复数 FFT 与后处理分开导出中间结果。
用极小手算例核索引，再覆盖生产窗口；参考和 RTL 同源系数不是完整独立证明。
整数逐码一致时使用 atol=rtol=0。
浮点容差来自量化、舍入、输入噪声和归约误差预算，不根据失败值临时扩大。
输出中的可变计时与状态元数据另存，数值比较范围事先明确。
`compare_numeric.py` 只比较所给 JSON，不会生成参考或证明单位正确。

## 单元与接口覆盖

| 输入/场景 | 要发现的问题 |
|---|---|
| 零、DC、非零偏置 | 状态未清、均值/直流定义、输出旧值 |
| 单脉冲/边界脉冲 | 抽头方向、延时、窗支持区间、抽取相位 |
| 满幅正负、交替符号 | 符号扩展、溢出、饱和和舍入 |
| bin 对齐/非对齐正弦 | FFT 顺序、泄漏、窗校正、bin 映射 |
| 多频/邻带/弱信号 | 必需频带覆盖、量化下限与串扰 |
| 不同通道/窗长/速率 | 共享核串扰、索引、残留状态 |
| READY 间歇与随机背压 | valid/payload 稳定、计数、丢包与重复 |
| reset/取消/超时/连续作业 | 状态恢复、旧结果混入和窗口身份 |

AXI-Stream 常见检查是 VALID 已置而 READY 未到时保持 VALID 与 payload 稳定。
同时核 TLAST/TKEEP 是否属于协议、其含义和宽度转换后的映射。
AXI-Lite 的地址/数据通道独立握手，不能假定同周期到达。
寄存器读取成功不等于计算完成；DONE、结果冻结、下一次开始需无歧义。
DMA 使用实际缓存一致性规则；不能把 CPU buffer 地址未经契约就当总线地址。
这些原则不替代当前厂商协议规范和 IP 配置。

## 从可解释瓶颈选择优化

- 资源瓶颈：比较对称 FIR、乘法复用、存储映射、核共享与位宽压缩。
- 吞吐瓶颈：比较流水、分块、双缓冲、批量传输和并行通道。
- 控制瓶颈：比较批量寄存器/结果读取和 DMA；控制数据少时保留简单接口。
- 时序瓶颈：先看真实关键路径与扇出，避免只凭 RTL 行数推断。
- 系统瓶颈：若 PL 已快而搬运占主导，进一步缩短核周期未必改善端到端。

每次只对已识别瓶颈提出变化，保持输入与输出语义。
核共享要比较排队时间和最坏等待；并行化要比较资源与带宽。
跨时钟加流水会改变延时契约，需要更新对应 testbench。
直接换 FFT IP、N 或缩放策略后，重新校验全部相关指标。

## 验证分层与报告身份

1. 主机参考/单元：证明算法和边界实现，不证明厂商 IP。
2. RTL 仿真：注明真实 IP 模型或 stub；stub 不能证明 FFT 数值。
3. 综合/布局布线：绑定源提交、约束、系数/IP配置、工具与完整器件。
4. 板端合成输入：证明该载荷的数值或接口，不证明真实传感和机械类别。
5. 实际来源数据：再核接线、校准、数据完整性和独立任务效果。

`summarize_vivado.py` 支持的报告格式可严格摘要，但解析成功不代表验收成功。
原始 setup/hold/pulse、DRC、CDC、未约束路径与警告仍需单独审核。
资源 Used/Available 和器件必须来自同一构建，未知格式保持失败。
自写 Tcl 查询只能证明查询到的对象，不能声称跨厂商可直接使用。

## 同输入 A/B 的最小记录

固定输入 SHA、参数/schema、时钟、编译选项、设备与计时范围。
写明预热次数、重复次数、时钟来源、同步点及汇总统计。
分别记录 `prepare/transfer_in/compute/transfer_out/consume`。
CPU wall time、PL cycles、吞吐和 UI 响应不能混成一个速度值。
先通过数值门槛，再输出性能比；失败或未测项保持可见。
结果摘要应可追溯到实际运行载荷和原始测量，不复用旧报告数字。

## 可直接替换的优化提示词

```text
优化[模块/接口]，基线为[提交/参数与原始报告]。
输入：[通道、窗长、格式、速率]；时钟/器件：[已知值]。
数值契约：[位宽、舍入、饱和、FFT顺序/缩放]。
目标：[资源/吞吐/端到端时延]；不可改变：[输出与兼容行为]。
黄金参考：[独立来源]；验收：[容差及预算依据]。
先用现有证据定位瓶颈，提出最小可验证改动，
输出逐级对照、接口失败路径、同输入A/B与真实实现身份。
区分stub、真实IP仿真、实现报告、实板合成和真实来源数据。
```

## 停止条件

参考本身不确定时先澄清语义，不能以 RTL 输出反向定义正确答案。
器件/约束或 IP 配置不匹配时，不沿用时序与资源结论。
性能范围不一致或结果不一致时，不发布加速倍数。
可复用经验与历史证据边界见 [evidence.md](evidence.md)。
