# PL黄金参考与实现优化

## 冻结数值契约

记录输入窗、单位、滤波系数哈希、位宽、符号扩展、累加、舍入/饱和、FFT顺序/缩放与统计定义。黄金参考尽量独立于RTL，逐行翻译可能复制同一错误。接口明确DONE/INDEX/READY、窗口身份和冻结读取语义；地址成熟不等于结果完成。功率、幅度谱与PSD分别定义。

## 分层验证

1. 单元覆盖直流、脉冲、满量程、饱和、非零均值、边界索引、滤波器历史与全部采样档。逐码一致要求atol=rtol=0，浮点容差由量化预算确定。
2. 集成区分厂商真实IP模型与stub，核对Hann、复码、指数和索引。单正弦弱必需频带不能覆盖全部指标；保留not_evaluated，用明确标为合成的多频输入补覆盖，不从失败倒推放宽阈值。
3. 在目标器件/时钟/真实约束下实现，保存原始routed报告、源/系数/IP/工具身份。用summarize_vivado.py严格摘录支持的表格；未知格式失败，不用旧数字补字段。另查setup/hold/pulse、DRC、CDC、未约束路径与警告，CLI解析成功不等于合格或报告属于当前bitstream。
4. 只有目标板操作已获授权时，才比较同原码/配置的硬件与参考，保存ELF/驱动/bitstream身份。合成实板数值不证明机械准确率。

## 同输入A/B

分开测滤波器周期、送料、结果读取、FFT、特征和UI，固定输入SHA、配置、计时范围、预热、次数与统计。先核结果一致再比较速度。完整payload可明确排除本来变化的周期计数，但不能无说明忽略其他差异。局部周期下降、板端API耗时与整机响应是不同证据，不合并成整机加速。

方法案例及未公开历史证据的边界见[e03/e04/e05](evidence.md)。本公开候选没有重跑真实实现或板端；合成CLI回归仅证明相应工具行为。
