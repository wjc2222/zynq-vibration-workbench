# 多通道工程 UI、量程与可见性能

用于触屏、桌面、网页或嵌入式操作界面的状态与响应设计。
本方法不要求 Qt、特定分辨率、固定通道数或振动故障四分类。
核心是让采集/分析的真实状态可观察，同时限制显示对权威通路的影响。

## 输入与输出契约

输入：目标显示尺寸、输入方式、用户流程、异步任务、数据/模型状态与保存要求。
输出：状态表、显示数据契约、响应预算、持久化策略及渲染/交互验证。
设计界面前先读 [采集](acquisition.md) 和所需 [PS 状态](ps.md)。
用 [acceptance-plan.md](../templates/acceptance-plan.md) 分开记录软件交互与物理验收。

| 状态输入 | 界面必须传达 | 可操作动作 |
|---|---|---|
| 无设备/无数据 | 来源未就绪，不显示伪实测波形 | 打开数据、配置、查看原因 |
| 正在采集 | 当前 job、速率、已收/已保存位置 | 规格允许的停止或取消 |
| 正在排空/封段 | 已停止输入但尚未持久完成 | 等待、查看可恢复错误 |
| 分析中 | 输入窗/配置和真实进度或忙状态 | 允许取消时保留一致结果 |
| 模型缺失/不兼容 | 缺少哪个 schema/参数 | 选择/训练合法模型 |
| 完成/失败 | 最终状态、有效输出位置、失败原因 | 打开结果、重试或恢复 |
| 模拟/回放 | 明确来源标记 | 不能伪装为设备实时数据 |

“采集停止”“文件已保存”“分析完成”不应共享一个模糊完成标志。
错误消息要保留任务关联，迟到回调不能把新任务状态改回旧状态。

## 先决定显示数据从哪里来

显示可采用 min/max 包络、降帧、抽稀或图像缩放。
这些视图数据保留来源窗、单位、时间范围和质量标记。
需要均匀采样的 FFT/模型使用正确原码窗，不复用绘图稀疏点。
预览可使用有界最新帧槽；原始文件不能因为绘图慢而静默缺样。
通道增加后明确绘制上限、叠加/分页/选择方式和不同单位的轴。
图表标题、单位、通道色和质量状态应随实际配置更新。

## 用状态而非整页禁用管理可达性

无数据只禁用依赖数据的动作，不应使量程、设备配置或帮助入口失联。
正在计算可禁修改当前作业参数，但保留不影响作业的查看动作。
异步完成时核 job/session/config 身份，不接收旧窗口结果。
用户取消后区分“已发取消请求”“任务已停止”和“输出是否保留”。
长任务放在适当执行器，主线程只处理可控时间的状态更新和绘制。
具体线程模型随框架变化，不把某个 Qt worker 类作为通用要求。

## 自动与固定量程是两个状态

每个显示模式/单位组合可保存 `auto/fixed, ymin, ymax`。
固定 Y 后 X 方向缩放、平移和新数据刷新不能偷偷重新自动缩放。
自动量程应考虑无数据、单值、NaN、离群点和通道启停。
显示裁切与 ADC 削顶不同：前者是视图范围，后者是数据质量。
不同量纲不应共用未注明的轴；电压切加速度时重新验证范围和转换。

一种电压到加速度的单位示例为：
`a = 1000 × (V - bias) / (gain × S)`，
其中 S 的单位是 mV/(m/s²)，gain 为无量纲增益。
若传感器给 mV/g，先明确采用的 g 定义再换算。
这只是单位公式，不证明传感器已标定，也不要求所有任务使用该单位。
改变显示单位不能暗改模型输入或已保存原始记录。

## 配置持久化按平台适配

先核可写且实际持久的配置根，不按 HOME、用户名或分区号猜。
Qt 可使用 QSettings，网页/RTOS/裸机使用其实际存储 API。
配置包含 schema/version、合法范围、默认行为和升级失败策略。
不能将“API 返回成功”直接写成“物理断电后不丢”。

分别验收：
1. 更改后进程内读取。
2. 配置文件/存储内容重开。
3. GUI 关闭重开。
4. 正常软件重启。
5. 实际掉电和冷启动，仅在相关操作已授权且实际执行时记录。

用户选择“自动”与“固定”应可重现，损坏配置不能导致无法启动。
新版本配置不兼容时明确迁移或回退，而非静默忽略全部用户设置。

## 响应预算要注明观察点

| 度量 | 可证明 | 不能自动证明 |
|---|---|---|
| worker 耗时 | 某任务代码区间服务时间 | UI 已显示 |
| 队列年龄 | 消息从入队到消费的等待 | 物理触摸到光子时延 |
| paint/渲染耗时 | 一次绘制或帧生成时间 | 用户设备显示已更新 |
| 操作到状态变化 | 该自动化或仪器定义的端到端路径 | 其他分辨率/输入设备行为 |
| 原始保存延时 | 某数据到指定存储事件的时延 | 掉电持久可靠性 |

时间戳来自不同时钟时先校准；不可直接相减得到“精确延时”。
报告负载、采样窗口、预热、次数、分位数口径及丢帧/丢消息计数。
优化应同时检查 CPU/内存、绘图帧率和原始数据完整性。

## 渲染与交互矩阵

覆盖实际分辨率、缩放比例、语言和输入方式。
至少检查空数据、满负载、多通道、长路径、长标签、异常信息和模型不兼容。
验证按钮可达、文本不裁切、弹窗可关闭、进度可取消、错误可恢复。
固定 Y 的复验包括刷新、切模式、开关通道、载入新文件和重开配置。
截图只能证明该状态的画面，不能代替交互或硬件持久化测试。
Xvfb/xcb 等隔离环境用于定位显示后端污染；失败日志仍须保留。
自动化 Qt/uinput 事件与真实手指是不同证据类型，framebuffer 也不是实物照片。

## 可替换的 UI 提示词

```text
为[显示尺寸/输入方式/框架]改进[具体流程]。
数据：[通道、单位、来源与预览方式]；异步任务：[列表]。
状态：[空闲/采集/排空/分析/完成/失败]及作业身份：[字段]。
量程与持久化：[要求、实际配置根]；响应预算：[观察点/负载]。
先给状态表与数据/控制所有权，保留权威原始通路；
再实现最小修改，渲染空数据、长文本、满负载和不兼容状态，
验证固定量程、取消及配置重开，分别报告自动化和物理未测项。
```

## 失效条件

未知目标分辨率时可做结构方案，不能确认最终无裁切。
未知存储根或只在 RAM 中回读时，不报告持久化完成。
未做实际硬件试验时，物理触摸/掉电项保持未验证。
经验来源及本案例失败见 [evidence.md](evidence.md)。
