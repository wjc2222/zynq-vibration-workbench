# UI、量程与可见性能

先画出实际分辨率下的核心流程：来源/采集设置→采集/停止及已保存状态→打开BIN→人工标注/样本库→建立模型→待测推理→结果/质量/模型身份。长计算移到worker，UI显示真实进度/取消/失败；不要用固定延时伪造完成。

## 从真实量程失败提炼的做法

曾出现无数据时禁用整个AnalysisPane而使量程入口不可用、重绘/模式切换覆盖用户固定Y、配置留在RAM重启丢失。修复应分别针对状态和持久化，而非只增加一个下拉框：

- 无数据时只禁依赖数据的动作，量程输入保持可达。
- 按时域V、频谱V、加速度m/s²分别保存auto/fixed和上下界；固定Y后继续允许X导航，重绘不能再次自动缩放。
- 配置定位到已核实的可写持久数据根，不猜HOME或SD分区；验证写文件、GUI关闭重开、正常重启、物理掉电四个不同层级。
- 区分显示裁切与ADC削顶。传感器灵敏度应有铭牌/校准来源，不从画面猜单位。

加速度显示可按明确的单位契约换算，例如`a=1000*(V-bias)/(gain*S)`，S为mV/(m/s²)。若原铭牌是mV/g，先除9.80665转换。输入参数不证明已标定；其变化不应暗改算法输入特征。

## 验证可操作性

在真实目标分辨率渲染空数据、加载/采集、三通道、长路径、长标签、警告、样本不足、模型无效/版本不符等状态，检查遮挡/裁切/按钮可达/文字。用自动化手势检验固定Y、模式切换、重开配置；有授权时读取真实板端framebuffer并校验来源和图像。

隔离Xvfb/xcb与XDG配置可定位WSLg/offscreen污染，原失败日志仍保留。软件注入的Qt/uinput手势不是物理手指测试，framebuffer回读不是相机照片。性能记录具体是paint时间、队列年龄还是完整API；不能把队列p95或截图时间叫物理触摸延迟。

方法案例见[e07](evidence.md)。配置写入、关闭重开、软件重启、物理掉电、自动化手势和真实手指分开验收；本公开候选没有新做其中任何板端验证。用户暂停板测时不能因文档列有步骤而恢复板端操作。
