# 面向具体目标的重建、部署与回滚

用于从源码得到可核验载荷，并在明确目标上进行最小变更。
可适配 Linux、裸机、RTOS 和其他启动链，不固定串口、分区或文件名。
只要求资料/主机验证时完成相应范围；文档中的部署步骤不构成板端操作授权。

## 输入与输出契约

输入：源码身份、工具/SDK、目标 ABI、启动链、目标身份、存储现况和允许变更。
输出：可重建载荷、目标专属计划、备份/回滚、读回与运行验收记录。
复制 [deployment-plan.json](../templates/deployment-plan.json) 形成审查计划。
该模板默认 `planning_only: true`，没有执行器，不可直接作为刷写配置。
真实板卡身份等私人值保留在本地，不写进公开示例。

## 先在主机闭合可重建性

检查可信来源的外部 SHA、成员路径及已有清单。
解压器须拒绝绝对路径、目录越界和不受支持链接；审计脚本不是安全解压器。
使用新源码路径与树外构建目录，避免读到开发机旧输出。
记录源码提交、依赖版本、编译器、IP 参数、链接布局及构建命令。
验证实际输出存在、架构/ABI正确，并绑定 ELF/bitstream/镜像 SHA。
host 编译通过不自动证明 ARM/RTOS 构建、目标运行或全新离线重建。

| 平台 | 重建时另核对 |
|---|---|
| Linux/SoC | 内核/UAPI、rootfs、动态加载器、共享库、设备树、模块 ABI |
| 裸机 | 链接脚本、内存区间、中断向量、启动代码、缓存与 DMA |
| RTOS | BSP/port、调度/栈、DMA 缓存、文件系统和配置持久化 |
| FPGA 配置 | 器件/封装、时钟/IO约束、IP许可证、bitstream对应源 |
| PYNQ | 目标镜像/版本、overlay/HWH配对、DMA与Notebook API |
| 其他厂商 | 等效工具、载荷格式与启动机制，不能直接执行 Vivado 入口 |

PYNQ 一行是移植检查，不代表本 Skill 已实现或验证通用 PYNQ 方案。

## 目标身份与存储只读预检

在用户已要求相应板端操作后，先读取身份，不从旧日志复用。
可用字段依平台而定：JTAG链、UART启动信息、器件/板型、boot_id、介质身份。
Linux可另取分区表、起始/大小、文件系统、挂载模式、空间和启动配置。
裸机/RTOS需确认 flash 分区、bootloader、地址范围与擦除粒度。
没有某字段不自动阻止一切；需说明替代身份依据及剩余风险。

确认以下关系：
- 当前连接对应哪块目标板，使用哪个调试/串口通道。
- 介质与启动链实际读取哪份载荷，是否存在多套启动分区。
- 待写范围与保存原始数据、模型、校准、配置的范围是否重叠。
- 当前载荷及必须保留文件的字节身份。
- 备用启动/恢复入口和回滚执行条件。

“同型号”不足以推断相同 SD 布局、flash 分区或载荷。
两分区、三分区或其他布局以当前事实解释，不按 p1/p2 名称猜用途。
身份或边界无法确定时停在计划，继续与该未知项无关的主机验证。

## 形成最小可审查变更

| 计划项 | 必须有的内容 |
|---|---|
| 目标 | 当前板/介质身份和发现时间 |
| 范围 | 哪些文件/地址改变，哪些必须保留 |
| 候选 | 来源、SHA、尺寸、兼容内核/驱动/IP/应用 |
| 备份 | 原始对象、备份路径、完整性验证 |
| 回滚 | 触发条件、旧载荷身份、恢复路径 |
| 发布 | RAM试运行或持久更换，顺序与同步语义 |
| 验收 | 读回、运行身份、保留数据、启动与功能项 |

不默认格式化、重分区或删除未知内容。
不要把旧模型自动迁移到语义已变的新特征/采样配置。
备份存在但未核 SHA/可读性时，不能把回滚写成已就绪。
可选 RAM 试运行也需明确覆盖内存范围、是否影响当前采集和恢复方式。

## 发布与启动验收要分层

先核写入后的尺寸/SHA或适用的读回校验。
有文件系统时，按实际平台完成同步、卸载或恢复安全只读状态。
不要在未安全卸载的外接存储上直接重启。
通过独立运行 receipt 核对实际软件/驱动/FPGA身份，而非只看复制日志。

验收状态分别记录：
1. prepared：候选和计划已准备。
2. written/readback：写入并读回匹配。
3. running：当前运行身份已核对。
4. software reboot：正常软件重启后运行。
5. physical cold boot：实际断电后启动。
6. application/data：采集、保存、触摸、模型与真实任务分别验证。

前一项不能代替后一项；正常重启不等于物理冷启动。
实板合成数值通过不等于真实传感器采集或独立机械分类通过。
已有暂停板测要求时不因改了文档或脚本而恢复板端动作。

## 可直接替换的部署提示词

```text
准备将[候选产物及SHA]部署到[明确目标]。
允许操作：[只读检查/RAM试运行/指定持久变更]。
保护：[原始数据/校准/配置/旧载荷]；当前资料：[启动与存储信息]。
先确认当前目标身份和实际布局，不套用本仓库板型或分区号。
输出deployment-plan.json：范围、候选、备份、回滚与逐项验收。
未知地址/启动路径/介质用途保持未知，不执行猜测性写入。
操作已获授权时按最小范围执行，保存实际读回和运行身份；
软件重启、物理冷启动、触摸、原码和任务效果分别报告。
```

## 交付闭环与失效条件

接收者应拿到实际入口、依赖、源/产物身份和仍需外部取得的组件。
只列文件路径不等于可重建，只有复制截图不等于运行验收。
工具链或驱动/IP ABI不匹配时停在兼容性分析，不跳过检查硬启动。
备份/恢复入口不可靠且变更不可安全恢复时，先解决恢复方案。
掉电、触摸或真实采集未执行时明确未验证，不合并为“上板完成”。
