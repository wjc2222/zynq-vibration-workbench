# 从需求到工程契约与 PL/PS 划分

用于新建或移植采集、信号处理、视觉、控制和嵌入式推理工程。
复用的是决策和验证方法；ADC 型号、通道数、操作系统与模型由新工程定义。
本仓库振动工作台只是一个已知案例，不是必须复刻的产品。

## 输入与输出契约

先复制 [project-contract.json](../templates/project-contract.json) 和 [acceptance-plan.md](../templates/acceptance-plan.md)。
前者是人工规划格式，带 `planning_only: true`；不能直接当作寄存器配置或部署命令。
`null` 表示尚未确认，不能解释为零、默认地址或已通过。
工程预算工具的独立输入见 [examples/portable/](../examples/portable/)；不要将整个规划契约直接传给它。

| 输入 | 最少内容 | 未知时仍可推进 |
|---|---|---|
| 任务 | 输入→输出、目标用户、允许延时、错误后果 | 整理需求和可测指标 |
| 目标平台 | 完整器件、板型、存储、时钟、OS、工具链 | 主机参考、协议和静态预算 |
| 数据 | 通道、单位、采样/帧率、格式、来源与代表范围 | 合成边界输入，标为 synthetic |
| 实现现状 | 可重建入口、受保护基线、源与产物身份 | 只读列出依赖和缺口 |
| 约束 | 资源、带宽、功耗、延时、持久化要求 | 列出未知约束，不填估计通过 |
| 验收 | 参考、容差依据、统计口径、硬件边界 | 形成待填写验收表 |

交付三项：可审查工程契约、PL/PS 方案比较、逐项验收计划。
每项结论注明事实、测量、估算或假设；估算不能自动升级为测量。

## 把功能需求改写为可观测条件

不要只写“实时”“高精度”或“界面不卡”。
把要求落实到输入范围、负载、观察点、阈值、超时和失败动作。
例如“持续录制”至少包括最大输入速率、时长、写盘尾延时和停止尾段语义。
例如“低延时识别”需说明从原始窗最后一个样本到哪一个结果可用事件。
例如“支持多通道”需说明数量上限、通道布局、单位和通道增减后的 schema 规则。
实际阈值由任务给定或通过基线建立；不要继承本案例的数值。

按以下顺序澄清冲突：
1. 明确不能丢失的权威数据与可丢弃的辅助数据。
2. 明确不能改变的语义，如采样时间、标签、定点舍入和模型输入顺序。
3. 列出必须满足的上限，如资源、最坏服务时间、功耗或存储容量。
4. 再确定可优化的指标和可接受的降级行为。

## 选择 PL 与 PS 的边界

| 候选功能 | 适合 PL 的依据 | 适合 PS 的依据 |
|---|---|---|
| 采样时序与帧完整性 | 硬时限、并行接收、逐样本稳定吞吐 | OS 驱动、文件管理、错误展示 |
| FIR/FFT/图像流水 | 固定算子、稳定尺寸、足够复用、数据可流动 | 尺寸频繁变化、低占空比、开发成本更关键 |
| 模型推理 | 参数适配、带宽/资源可承受、实测收益覆盖搬运 | 小模型、控制逻辑多、现场更新频繁 |
| 标注、训练、配置 | 少量固定预处理可下沉 | 分组验证、持久化、复杂策略、可维护性 |
| UI 与日志 | 显示控制器或既有视频通路 | 交互、状态、任务调度和可读诊断 |

不要以“算子可综合”作为迁移充分理由。
先比较端到端预算：`T_total = T_prepare + T_transfer_in + T_compute + T_transfer_out + T_consume`。
只有相同输出语义成立后，才比较时延、吞吐、资源与实现风险。
AXI-Lite 适合控制和低速结果；是否改 DMA 取决于有效搬运量和测量。
共享核节省资源但增加调度和窗口身份复杂度；独立核增加并行度和资源。
可用 PS 基线、PL 原型和共享/并行方案三列，不强制所有任务都使用 PL。

## 边界接口必须能判定完成和失败

控制面记录 ABI 版本、状态、配置、开始、取消、超时和错误恢复。
数据面记录长度、顺序、字节序、对齐、有效位、包边界与背压。
把“已接收”“已计算”“结果已冻结”“已持久保存”拆成不同事件。
结果必须可关联输入窗口或任务身份，防止读取前一次作业的数据。
跨时钟、跨进程和跨设备分别描述所有权和同步机制。
改变通道数、窗口长度或模型输入时，应更新配置/schema，而非只改数组大小。

## 换工程时怎样适配

| 改动 | 必须重新确认 | 可继续复用 |
|---|---|---|
| 3 通道改 2/8/16 通道 | 总带宽、帧跨度、DMA 布局、UI 通道选择 | 权威原码与预览分离、故障注入方法 |
| 并行 ADC 改 SPI/I²S/以太网 | 时钟来源、丢包/重排、帧和时间戳定义 | 连续区间判定、独立落盘验证 |
| 振动改声学/电流/图像 | 单位、抗混叠、窗口、校准和标签 | 数值黄金参考、源与结果身份绑定 |
| Linux 改裸机/RTOS | 中断/DMA、内存、缓存维护、持久化 API | 所有权、超时、队列上限、回滚要求 |
| FFT 改其他尺寸/实数格式 | bin 语义、缩放、窗口能量、吞吐预算 | 分层参考、同输入 A/B、实现身份 |
| RF 改 SVM/CNN/回归 | 特征/张量 schema、资源和验证指标 | 按独立组划分、训练折拟合、模型绑定 |
| Zynq 改其他 FPGA/SoC | 厂商工具、总线/时钟/IP 和驱动 | 契约、预算、失败路径与验收分层 |
| 改用 PYNQ | overlay/HWH、DMA 缓存、Notebook/API 生命周期 | 方法与数据契约；不能宣称本包已验证 PYNQ |

## 直接可用的需求与划分提示词

```text
使用此 Skill 建立工程方案，不先套用仓库的振动参数。
任务：[输入来源] → [处理] → [输出/使用者]。
平台：[器件/板型/OS/工具版本]；已知接口：[总线/ADC/网络]。
数据：[通道数、单位、格式、峰值速率、代表时长]。
保护基线：[源提交及不可改变语义]。
要求：[吞吐、端到端时延、资源/功耗、数据保存规则]。
允许操作：[资料分析/隔离实现/构建/指定板端操作]。
先填写 project-contract.json 的已知项并列出关键未知项；
比较 PS 基线与至少一个有实际依据的 PL/PS 划分；
对每个方案输出接口契约、预算、失败路径和验收证据。
不要把估算或合成输入写成硬件测试结果。
```

## 决策停止条件与验收

协议未知不阻止主机参考开发，但阻止宣称真实输入已被正确解析。
器件/时钟/约束未知时，不给资源占用率或时序合格结论。
标签分组未知时，可以实现训练接口，不能报告独立泛化。
部署目标未知时停在可审查计划，不能猜地址、介质或启动路径。
预算不足时给出受影响要求和可选方案，由任务优先级决定取舍。

验收工程契约时检查：
- 每个成功条件可由实际观察或输出判断，且写出测量起止点。
- 每个关键未知项有获取方法和所阻塞的结论。
- 每条 PL/PS 边界都有有效数据、完成、超时和版本定义。
- 不同工程的通道/采样/OS/模型参数没有被案例值隐式固定。
- 估算、合成验证、真实 IP 仿真和板端验证分开报告。

经验来源与证据分级见 [evidence.md](evidence.md)。
