# 可迁移的采集、原始存储与实时预览

用于 ADC、音频、网络传感、图像帧或其他有时序关系的数据流。
先定义哪份记录是权威数据，再决定存储和预览如何共享输入。
通道数、器件、每样本位宽与帧格式均来自 [工程契约](adaptation.md)。

## 输入与输出

输入：协议描述、代表原始字节、设备/驱动 ABI、速率范围与连续性要求。
输出：字段表、解析器约定、带宽/缓冲预算、存储状态机、故障注入结果。
没有设备时可用合成字节流验证软件路径；输出必须标记 `synthetic`。
设备缺失不能自动切换模拟源并显示为真实采集。

| 字段 | 应确认的内容 | 不适用时 |
|---|---|---|
| payload | 类型、符号、有效位、通道顺序、帧跨度 | 不猜 packed 与 padded |
| 标识 | session/job、设备、配置或等效关联 | 使用受控文件/连接元数据 |
| 连续性 | 样本序号、时间戳、包序号或外部时基 | 记录无法观测的缺口范围 |
| 完整性 | CRC 算法/覆盖范围、长度、帧头与版本 | 无 CRC 时明确剩余风险 |
| source | 实际设备、模拟、回放、转换链 | 不以文件扩展名推断来源 |
| 停止 | 触发、在途数据、尾段、取消/失败 | 不假定收到 stop 即已落盘 |

CRC 的多项式、初值、反射、xorout 和字节覆盖范围都属于协议。
时间戳要说明单位、回绕、复位、单调性和它对应采样还是接收事件。
网络到达时间不能直接替代 ADC 采样时间。

## 先计算完整带宽与余量

对固定帧：`R_input = frame_bytes × frames_per_second`。
`frame_bytes` 包含包头、时间戳、校验、填充和对齐，不能只算有效 ADC 位。
对变长帧使用峰值与突发长度，平均速率不足以限定队列上界。
链路有效载荷还受编码、帧间隙、握手和协议效率影响。
UART 8N1 的理想字节上限为 baud/10；其他格式重新计算。
缓冲的最低预算可用 `B ≥ R_peak × longest_service_stall + burst_bytes` 估算。
该式不代表设备实际可满足；用实际写盘尾延时/调度抖动检查余量。
容量估算包含持续时间、索引、元数据、分段尾部和必须保留空间。
预算工具输入是独立 profile，见 [portable examples](../examples/portable/)。

## 用所有权划分数据通路

推荐比较以下两条逻辑通路，而非强制固定线程数：
- 权威通路：接收/DMA → 验证 → 有界缓冲 → 原始记录。
- 可降级通路：已验证数据 → 预览聚合/抽稀 → 最新可见帧。

存储慢时应按任务定义暂停源、背压、丢弃并计数或失败停止。
不存在“无限排队且仍实时”的实现。
UI 消费慢时可丢旧预览，但不能静默丢权威原码。
裸机/RTOS 可用 DMA 双缓冲和队列实现同样所有权，不必复刻 Linux worker。
DMA 非一致性平台需明确 CPU/device 所有权、缓存维护和内存屏障。
跨核/中断共享指针必须有可解释的发布/消费顺序。

## 原始文件发布与停止状态机

按任务选择文件或块存储；文件系统示例状态可为：
`idle → receiving → draining → finalizing → published`。
任何阶段均可转入带原因的 `failed`，取消语义需显式定义。
`received`、DMA committed、写入 page cache、介质持久化是不同状态。
使用临时名时，只能清理本 job 拥有的临时文件。
保存成功至少重开核对长度、帧数、边界和校验；强持久要求还需匹配平台的同步协议。
文件/目录同步和原子重命名依赖文件系统语义，不能据此直接宣称掉电不丢。
停止先阻止新输入或记录截断点，再排空已承诺数据，最后发布尾段。
失败保留已发布段，并记录最后有效位置；不要删除其他会话文件。

## 缺口如何影响分析

先判断哪一段样本真正连续，再交给需要均匀采样的算法。
CRC 错、序号跳变、配置改变或时基复位应切断当前有效区间。
FIR 历史、抽取相位和分析 ring 的重置/预热规则要一致。
不补零或拼接两侧样本来伪造无缺口窗口。
显示 min/max 包络、稀疏点和绘图插值不能直接输入 FFT 或模型。

因果 FIR 长度 T、抽取倍数 D、输出 N 点的一个常见有效窗需求是：
`raw_frames = T + (N - 1) × D`。
它适用于明确的首个完整卷积输出与抽取对齐约定。
若有预存历史、块重叠、非因果滤波或不同抽取相位，应重新推导。
先用极小手算窗核边界，再测试生产尺寸，避免共同偏移错误。

## 必测失败路径

| 注入 | 必须观察的输出 | 不足以算通过 |
|---|---|---|
| 短读/拆包/粘包 | 增量解析不越界，结束时报告不完整尾部 | 一次 read 恰好一帧 |
| 坏 CRC/长度/版本 | 拒绝并定位，不将坏帧计为有效 | 只输出一条泛化 warning |
| 序号/时钟回绕 | 按协议判定回绕或复位，保存依据 | 所有负差都当丢包 |
| 慢预览/慢控制 | 权威通路结果一致或显式按规格降级 | 图仍然刷新 |
| 慢存储/空间不足 | 有界队列、明确失败、尾段和旧段语义 | 进程不崩溃 |
| 采样率/通道变化 | 禁止混窗或形成新配置区间 | 数组长度正确 |
| stop/取消/异常退出 | 最后承诺位置、尾段状态可核对 | UI 文本显示完成 |
| 重复任务/迟到消息 | 不发布旧 job 的状态或结果 | 当前任务偶然未受影响 |

每项记录输入源、故障注入位置、预期、实际和输出记录 SHA。
对同一原码，预览帧数量变化不应改变文件内有效采样记录。
真实设备持续压力、接线、标定和掉电恢复需另做目标环境试验。

## 可替换的改造提示词

```text
对[源码入口]建立[通道数/ADC或协议]连续采集方案。
原始帧描述：[字段表/协议文件]；峰值速率：[值与单位]。
权威输出：[文件/块记录]；预览：[包络/点序列/图像]。
可丢弃内容：[明确对象]；不得丢失内容：[明确对象]。
停止/空间不足语义：[要求]；OS与DMA缓存：[已知信息]。
保护[现有原码格式/兼容ABI]，先画所有权与状态机，
计算完整帧带宽和最长停顿缓冲预算，再实现最小改动。
输出故障注入表及独立重开结果，合成与实测分别标记。
不要把预览平滑、CRC通过或文件存在写成已标定机械采集。
```

## 失效条件与下一步

输入时基未知时，不能把均匀接收间隔当成均匀采样。
设备无法背压且预算不足时，必须明确丢失或不可满足，不能靠扩队列隐瞒。
实际文件系统持久语义不清时，验收到重开校验，掉电项保持未验证。
本方法经验与局限见 [evidence.md](evidence.md)。
